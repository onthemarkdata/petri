# Petri Data Model Rules

## Composite Key Hierarchy

- Dish: `{dish}`
- Colony: `{dish}-{colony}`
- Cell: `{dish}-{colony}-{level}-{seq}` (level/seq are 3-digit zero-padded)
- Event: an opaque deterministic ID derived from the cell and execution coordinates

## Rules

- Append validated events through the storage API. Never update or delete event rows.
- Start and cancel durable runs through the execution backend.
- Research data and events live in SQLite; text exports are derived views.
- All verdicts MUST use the exact strings from the vocabulary above.
